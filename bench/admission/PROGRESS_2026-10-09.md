## Direction
Tier-aware admission control: per query, admit / queue / fuse, based on plan-derived GPU
footprint + tier holding its input (GPU / host over PCIe / disk). Supersedes "multi-query
batching" (loses when data is GPU-resident) and intra-query fusion (crowded: Sirius #1628,
IBM ADMS'26).

## Done
1. **Lit check** (novel only as a combination):
   - MultiQx-GPU, Wang et al., PVLDB 7(11) 2014 — footprint-based GPU admission. Cite as ancestor;
     plan-derived footprint admission alone is NOT a contribution.
   - Raza et al., CIDR 2020 — GPU data-transfer sharing across query batches (no admission).
   - GUST, Jiang et al., CIDR 2026 — PCIe as schedulable resource (analytics + inference).
   - Sirius draft PR #2008 (count-only cap, FIFO) and PR #2001 (memory-pressure work) — check overlap
     with maintainers.
   - Corrections for the Oct 9 doc: IBM ADMS'26 (Lammie et al.) is on Velox-cuDF, Sirius only cited;
     fuses general pipeline windows; 84–90% is a two-kernel case study. Yinan Li et al. PVLDB 18(11)
     2025 = CPU pre-filtering/bitvectors to cut PCIe, not footprint placement. 7.5x/9.5x = Funke et
     al. SIGMOD 2018 (not "HAWK"). GMT (ASPLOS'24) confirmed page-level, query-agnostic.
2. **Arrival simulation** (`sim/arrival_sim.py`, `sim/arrival_sim.json`), Q6 overlapping predicates,
   warm costs, conc capped at 16 in flight. Kill criterion 5 NOT triggered:
   - SF100 host: conc capacity 2.8 q/s vs fused 24.5 (K=16) / 33.7 (K=32 extrapolated);
     p95 at 50% load 1.67 s (conc) vs 0.72 s (greedy fuse). Fuse wins even at 10% load.
   - SF10 host: 27.8 vs 212 q/s; p95 at 50% 196 ms vs 97 ms.
   - SF100 GPU: conc 56 vs fused 37 q/s; fusion loses; regime-aware policy stays within ~10% of conc.
   - Caveat: first run of a new fused shape can cost up to ~0.7 s extra (JIT).
3. **Reanalysis of Sep 24 8-client bimodality** (inconclusive): bad runs have 0 OOM retries and 0
   fallbacks; rep5 and pt16 had slow *serial warm-up* (4.3–5.1 s vs ~2.75 s) => node interference
   for at least those; bad runs cluster after 02:50 but pt2/pt8 bad around good pt4.
4. **Reactive memory gate + memory logger** — patched and built, NOT yet run.
   Diff: `admission_patch.diff` (originals in `patch_orig/`). Env-gated, off by default:
   - `SIRIUS_MEMLOG=<csv>`: every 10 ms: gpu_alloc, gpu_reserved, gpu_avail, host_reserved, live, waiting.
   - `SIRIUS_ADMIT_GPU_BYTES`, `SIRIUS_ADMIT_GAP_MS`: admit only while current GPU allocated bytes
     <= threshold; at most one admission per gap. This is reactive, NOT pre-admission.
   - Driver: `./run2.sh <tag> <data> <clients> [--memlog] [--admit-gb N] [--admit-gap-ms M] [...]`
     -> `results2/`.
